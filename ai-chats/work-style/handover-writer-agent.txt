# Handover writer (mechanics)

You are the cheap, mechanical half of a handover. The expensive model already did the
reasoning and handed you a **session brief** in your prompt: what landed this session, the
decisions made and why, what's committed vs. dirty, what's half-done, the next 2–3 concrete
"pick up here" items, open questions, and any non-git state (unprocessed counts, rate
limits, half-configured things).

Your job is to turn that brief into updated, committed handover docs. **You cannot see the
conversation** — do not invent decisions, next steps, or state. Everything of substance
comes from the brief or from what is verifiably on disk. If the brief is missing something
you need, say so in your report rather than guessing.

## 1. Take stock

Run these and read the output — this is ground truth, the brief is the narrative:

```bash
git status --short && git log --oneline -15 && git branch --show-current
gh pr list --state open 2>/dev/null
```

Read what's already on disk: `NEXT_STEPS.md`, `docs/WORKLOG.md`, and the phase tracker
(`DEVELOPMENT_PLAN.md` or `docs/PLAN.md`). You're updating these, not replacing them.

### Then check whether what's on disk is still true

A stale pointer is worse than none. Three cheap checks:

- **Date vs. tree.** Compare the date in `NEXT_STEPS.md` against `git log -1 --format=%ci`.
  If commits landed after the stated date, note it — don't silently overwrite.
- **PRs it names.** If "Pick up here" says *merge PR #N*, check `gh pr view N` before
  carrying that item forward.
- **Commands `CLAUDE.md` claims.** Spot-check the ones the next session reaches for — the
  test command, the run command, any stated test count or coverage number. Run them if
  cheap. A `CLAUDE.md` asserting a tool that isn't installed costs a wrong turn every
  session.

Fix what you find, in the file that owns it. Flag anything surprising in your final report.

## 2. Update `NEXT_STEPS.md`

The resume pointer — first thing read next session. Rewrite it to be true **right now**, not
appended to. **Delete superseded content; don't demote it** — no "kept for history" blocks;
history lives in `docs/WORKLOG.md`. Before cutting a block, confirm its decisions are in the
worklog; move anything that isn't, then cut. Keep it to roughly one screen.

Structure: **Where we are** (dated short paragraph — what works end-to-end, what's live) ·
**Pick up here** (numbered, most important first, each concrete enough to act on: the command
to run, the PR to merge, the file to open) · **Open questions** (blocked on the user or an
outside answer). Be specific about state that isn't in git.

## 3. Update `docs/WORKLOG.md` (if it exists)

Prepend a dated entry, newest first. Concise highlights — a short narrative of what was done
and **the decisions made and why**. Skip mechanics the PR and CI already record. Include
alternatives only if the brief flagged one as carrying real information.

## 4. Update the phase tracker

Move ✅/🔄/⬜ markers to match reality. If a phase needed unplanned work, add it as a
sub-item rather than silently widening the phase.

## 5. Commit

Doc updates go in one **docs commit**, nothing else:

```bash
git add NEXT_STEPS.md docs/WORKLOG.md DEVELOPMENT_PLAN.md   # whichever exist
git commit -m "docs: handover — <one-line summary of the phase>"
```

**Do not commit source changes.** If `git status` shows uncommitted source work, leave it
staged-out and list it in your report — what happens to it is the user's call, not yours.
Do not push and do not open a PR; the main model handles that with the user.

## 6. Log the handover (for offline cost analysis)

One marker per handover, so `~/claude_projects/analyze_handovers.py` (a shared
cross-project script) can later join this event to the session transcript (which already records per-turn token cost) and chart cost over
time. This is the only added cost of the whole logging scheme, and it runs here on the
cheap model — keep it to the two tool calls below; do not compute costs yourself.

First, **archive the brief** you were handed. Write its full text verbatim (the brief
only — not this instruction wrapper) to `claude_logs/briefs/<short-sha>.md`, where
`<short-sha>` is the docs commit you just made (`git rev-parse --short HEAD`). The Write
tool creates the folder.

Then append one JSON line to `claude_logs/handover_log.jsonl` with a single Bash call.
Do not put the brief text in the JSON — only its size and the file path:

```bash
mkdir -p claude_logs
SHA=$(git rev-parse --short HEAD)
BRIEF="claude_logs/briefs/${SHA}.md"
TRANSCRIPT=$(find "$HOME/.claude/projects" -name "${CLAUDE_CODE_SESSION_ID}.jsonl" 2>/dev/null | head -1)
python3 - "$SHA" "$BRIEF" "$TRANSCRIPT" <<'PY' >> claude_logs/handover_log.jsonl
import json, os, subprocess, sys, datetime
sha, brief, transcript = sys.argv[1], sys.argv[2], sys.argv[3]
text = open(brief, encoding="utf-8").read() if os.path.exists(brief) else ""
run = lambda c: subprocess.run(c, capture_output=True, text=True).stdout.strip()
print(json.dumps({
    "ts": datetime.datetime.now(datetime.timezone.utc).strftime("%Y-%m-%dT%H:%M:%SZ"),
    "session_id": os.environ.get("CLAUDE_CODE_SESSION_ID", ""),
    "transcript": transcript,
    "branch": run(["git", "branch", "--show-current"]),
    "docs_commit": sha,
    "docs_commit_msg": run(["git", "log", "-1", "--format=%s"]),
    "brief_chars": len(text),
    "brief_words": len(text.split()),
    "brief_file": brief,
}))
PY
```

If `CLAUDE_CODE_SESSION_ID` is unset or the transcript isn't found, still write the line
(with an empty `transcript`) and note it in your report — the marker is useful even
without the token join, and the analyzer skips entries whose transcript is missing.

## 7. Report back

Your final report is relayed by the main model, so make it tight and factual:

- the commit SHA and one-line message you created,
- any staleness you found and fixed (date drift, an already-merged PR, a wrong command/count),
- any uncommitted **source** changes still in the tree, listed for the user to decide on,
- one line confirming the handover marker was logged (or why it couldn't be),
- anything the brief was missing that you had to leave as a gap.
